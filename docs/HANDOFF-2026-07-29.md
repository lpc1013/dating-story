## 1. 铁律（动代码前必读，违反即翻车）

### 1.1 技术栈与预览
- 纯静态：`index.html`(~55KB) + `js/`(29 模块) + `css/style.css`(88KB)，**无框架、无打包**。
- 本地预览：`serve.mjs`（Node http 静态服务，默认 `:8088`）。改 `js/*.js` / `css/*` 即时生效，走 `http://localhost:8088` 验证。
- PWA：`manifest.json` + `sw.js`（改资源后 sw 缓存可能返回旧版，调试需清 Cache 或加版本戳）。
- Node 用托管版：`C:\Users\Pengcheng_Li\.workbuddy\binaries\node\versions\22.22.2\node.exe`。

### 1.2 改代码红线
- **CSS 只改 `css/style.css`**，禁止在 `index.html` 写内联 `<style>` 或大量 inline style。模块用 `/* ═══ MODULE: <name> ═══ */` 分隔，规则顺序不乱动（低风险）。
- **JS 模块级变量用 `var` 不用 `const`**（const 重赋值抛 TypeError，历史踩过）。
- 搬移/改名函数须同步**所有调用方**（spawnFloatLabel/cameraFlash/showWeatherInfo 等曾漏导致崩溃级 ReferenceError）。
- 顶层全局状态（如 `gameState`）必须留在函数体外，勿卷进函数变局部 shadow。
- 用户确认存在的功能按钮（��� 🔧 开发者面板）**绝不因 grep 不到引用就删**——先问。

### 1.3 配图系统（最易翻车的铁律）
- 映射文件 `assets/asset-map.js`（`window.ASSET_MAP`）：`eventImages[英文子键][事件名]`、`gf[子键]`、`cnToSubs[中文天气]→子键数组`。
- 接图按 **(英文子键 + 事件名)** 匹配，**绝不按文件名编号/数组下标**（编号 ≠ 剧情顺序；多云两条线重名）。
- `cnToSubs` 必须与 `story.json` 的 `meta.weatherGroups` 中文键**完全一致**（晴天:[sunny,sunny2]、多云:[cloudy,cloudy2]、雨天:[rainy,rainy2]、雪天:[snowy]；gf 键用 `cloudy2` 非 `cloud2`）。否则 `*_2` 线 / `file://` 兜底事件图全缺失。
- 改 `story.json` 或加图后须重跑 `tools/build_asset_map.js` 同步 `asset-map.js`。
- **协作约定**：图片素材由用户生成/替换，我只管框架与接图逻辑，不擅自改引用、不替用户选图。

### 1.4 绝对禁区
- ❌ **禁用 `tools/rebuild-from-bak.js`**：它是把旧单文件 `index.html.bak`(460K) 反向拆出 `js/*.js` 的「反方向」脚本，执行会用过期 bak **覆盖掉今天对 js/*.js 的全部修复**（含 difficultyModifiers 修复）。验证一律走 `:8088` 模块化预览。
