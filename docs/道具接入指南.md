# 道具接入指南（如何新增一个道具）

本文档供**内容作者 / 文案**照做：在不动游戏运行逻辑的前提下，新增一个"约会小故事"里的道具。目标是让你后续加文案、加道具都能"游刃有余"——只要照三步走，不会漏、不会崩。

---

## 三步法

### 第 1 步：在 ITEMS 注册表登记

打开 `js/backpack.js`，找到 `var ITEMS = { ... };` 对象，在最后一个道具后面加一条（注意用英文逗号分隔上一个）：

```js
yourid: { id:'yourid', name:'道具名', icon:'🔑', color:'#f59e0b', bg:'linear-gradient(135deg,#f59e0b,#fbbf24)', desc:'一句话描述' }
```

字段说明：
- `yourid`：道具 id（全局唯一，见下方"现有 id 列表"，不要冲突）
- `name`：显示名（会用在获得弹窗、背包详情）
- `icon`：一个 emoji 当图标
- `color` / `bg`：主题色与渐变背景（直接复制上面格式改色值即可）
- `desc`：一句话描述（获得时显示在 toast 里）

### 第 2 步：在文案里挂上这个道具

打开 `data/story.json`，在你想挂的选项上加一个字符串字段：

```json
"reward": "yourid"
```

- 也可以用 `useItem`（选项需要"使用"某道具）/ `requireItem`（选项需要"持有"某道具前置）；
- 若想整条事件级发放，可用事件对象的 `giveItem` 字段。
- **建议**：把道具挂在"非最优 / 不起眼"的选项上，让它成为彩蛋，与文案情感联动，而不是摆在主角面前强塞。

### 第 3 步：跑静态测试确认没漏登记

在项目根目录运行：

```
C:\Users\Pengcheng_Li\.workbuddy\binaries\node\versions\22.22.2\node.exe tools/test-flow-static.mjs
```

看输出里的 **(E) 道具 reward/useItem/requireItem 引用一致性** 块：
- 若全部 PASS → 搞定。
- 若某条 **FAIL**（如 `reward 引用缺失: yourid`）→ 说明第 1 步漏登记了，回去补第 1 步，再跑一遍。

---

## 注意事项

- **道具 id 全局唯一**：不要与"现有 13 个"冲突（列表见下），否则会覆盖既有道具。
- **收藏家成就自动统计**：只要道具被 `acquireItem` 获得，就会写入 localStorage `collected-items` 持久集（跨周目累积，独特道具数 `≥9` 解锁"收藏家"）。**无需手动改成就逻辑。**
- **漏登记不会崩**：若 story.json 引用了未注册的 id，`acquireItem` 会用兜底图标 📦 + `console.warn` 提示，游戏照常跑、不丢道具；但**图标/描述会缺失**，所以务必补登记（第 1 步）以免体验打折。
- 静态测试 (E) 块是"防呆护栏"：日常加道具后跑一遍，能在提交前就发现漏登记。
